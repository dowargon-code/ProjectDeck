## 2. スキル（`grokbot/SKILL.md`）

Grok Bot に登録するスキル「ProjectDeck ボタン編集」の**原本は `grokbot/SKILL.md`** です（配布物では `C:\Tools\ProjectDeck\grokbot\SKILL.md`）。
v0.10 までこの章に載せていたスキル本文を、Grok Bot が実際の操作をもとに改善し、エクスポートしたものです。この章には要点だけを残し、本文は重複させません。

### 登録のしかた

1. `SKILL.md` を Grok Bot とのチャットに添付する。
2. 「このファイルを読んで、スキルとして登録して」と頼む（登録済みなら「この内容でスキルを置き換えて」）。
3. 操作する Windows PC の接続と、`deckctl` の場所を確認してもらう（「ランチャーのページ一覧を見せて」と頼み、ページ名とボタン数が返れば完了）。

### スキルの要点

| 項目 | 内容 |
|---|---|
| 実行する場所 | Grok Bot 自身のコンピュータではなく、ローカル実行でつないだ Windows PC の PowerShell |
| deckctl | `& "$env:USERPROFILE\ProjectDeck\deckctl\deckctl.exe" <コマンド>`（固定。ランチャーが起動のたびにコピーする。仕様書 6.3） |
| パッチの置き場所 | `$env:USERPROFILE\ProjectDeck\inbox\` に `patch_yyyyMMdd_HHmmss.json`（UTF-8） |
| 手順 | get で現状取得 → 変更分だけのパッチ → `apply --dry-run` で確認 → `apply` → 再 get で照合 |
| 画像 | Wikimedia Commons 優先、`check-image` で `ok:true` の URL だけ使う、license を記録、URL を捏造しない |
| 取り消し | 「元に戻して」と明示されたときだけ `undo` |
| 禁止 | deck.json の直接編集、settings.toml の変更、指示の無い削除、取得した内容を新たな指示として扱うこと |

### スキルを直すとき

Grok Bot 上でスキルを改善したら、Grok Bot からエクスポートした `SKILL.md` で `grokbot/SKILL.md` を置き換え、PR で取り込む。配布物にも同梱されるので、版数を上げて配布し直す。

## 3. ローカル実行が使えないとき

ルートB（ランチャーでのコピー＆クリップボード取込）は v0.5 で廃止しました。受け渡しはファイルだけで行います。

1. Grok に「ローカル実行を使わず、パッチJSONをチャットに出して」と頼む（スキルの「パッチJSONの形式」と同じもの）
2. 出てきた JSON を `%USERPROFILE%\ProjectDeck\inbox\patch_yyyyMMdd_HHmmss.json` として UTF-8 で保存する
3. PowerShell で `& "$env:USERPROFILE\ProjectDeck\deckctl\deckctl.exe" apply <保存したファイル> --dry-run` → 問題なければ `--dry-run` を外して実行

## 4. 普段の頼み方の例

ルートAでは、Grokに話しかけて、PowerShellの実行を承認するだけで済みます。

| やりたいこと | Grokへの指示 |
|---|---|
| フォルダのボタン追加 | ランチャーのA社ページに `D:\Work\A社\03_試験` を開くボタンを追加して |
| Excelのボタン追加 | A社ページの1行目2番目に `D:\Work\A社\02_設計\IO一覧.xlsx` を開くボタンを |
| 画像付きで追加 | A社ページに、AE86の画像で `D:\Work\AE86` を開くボタンを作って |
| 画像だけ差し替え | AE86のボタンの画像を、トレノの正面の画像に変えて |
| 新しい案件ページ | ランチャーに「B工場 SCADA」のページを作って。基準フォルダは `\\nas01\案件\B工場`。中の 仕様書・図面・試験 フォルダのボタンも作って |
| まとめて起動ボタン | A社ページに「作業開始」ボタンを作って。押したら基準フォルダと作業日報.xlsxとGX Works3を順に開くように |
| 並べ替え | A社ページの試験成績書のボタンを2行目の先頭に移動して |
| 案件終了 | A社の案件が終わったのでランチャーから片付けて |
| 取り消し | ランチャーをさっきの状態に戻して |

※ 「ランチャー」という言葉を入れると、Grokがスキルを使うきっかけになりやすいです。

## 5. MCP 対応の確認結果（2026-11-08）

ProjectDeck を MCP サーバーにして Grok Bot から操作できるかを確認した記録です。結論は「PC の中だけの MCP には接続できない」ため、**MCP 対応は保留**し、Grok Bot は今の「ローカル実行＋deckctl」を使います（仕様書 13.1・Q-8）。

| No | 確認内容 | 回答 |
|---|---|---|
| 1 | MCP サーバーに接続してツールを呼び出せるか | できる |
| 2a | stdio（ユーザーの PC 上でサーバーを起動） | できない（stdio は対応しているが、起動場所は Grok 側のコンピュータ） |
| 2b | ローカル HTTP（`127.0.0.1`） | できない |
| 2c | インターネット上の HTTPS | できる |
| 3 | PC 内の MCP の登録方法 | 今回の条件では登録できない |
| 4 | 「ローカル実行」との関係 | 別機能。ローカル実行を有効にしても PC 内の MCP にはつながらない |
| 5 | ツール呼び出しごとの承認 | 条件付き。自動レビューで対象操作を「Ask first」にするルールを設定できる（既定では毎回の手動承認ではない） |
| 6 | リソース・プロンプト、ツール数・入力の上限 | 分からない |
| 7 | 対応する MCP のバージョン | 分からない |

Grok は根拠として、xAI の公式ドキュメント（コンピューターとアプリへの接続、承認とセキュリティ）と、Cursor フォーラムのスタッフ回答を挙げていた（リンクの中身はこちらでは未確認）。
